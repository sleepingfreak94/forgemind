## Manual owner workflow

1. Use the explicit owner commands in [weekly summaries](./weekly-summary.md) to prepare a stable reservation before a new supervised run. For historical imports, explicitly attest their provenance and reservation timing; do not claim a new reservation existed during the old execution.
2. Preserve actual RunAuthority artifacts and pin their exact bytes in a manifest. Import through OwnerRunRecorder, which checks task, source, check-terminal digest and review bindings. Repeated identical imports return the existing record; revoked or conflicting replay is rejected. Failed, blocked and indeterminate outcomes retain their actual evidence.
3. Generate a validated summary from real RunHistory pages at a fixed watermark. WeeklySchedule config/status/disable/tick/result is disabled by default; an explicitly enabled owner tick persists summary and cursor atomically. No automatic runTask history wiring, OS daemon, external delivery or new inference is activated.
4. For [continuation](./continuation.md), inspect checkpoint source, policy, expiry, budgets and unresolved effects, then prepare with fresh runtime authority narrowed to the receiving role. On failure, stop and checkpoint before a separately scoped repair; unknown effects must be reconciled before resumption.
5. Use [qualification](./qualification.md) to create or verify historical evidence-consistency reports. Reports grant no current host, account, billing or deployment authority. Obtain required task checks and independent review before publishing task changes; merge and release require separate authorization.
