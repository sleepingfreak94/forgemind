# Automatic supervised run history

The trusted host can configure `runTask({ ..., history: { stateDirectory, verifyIndependentReview } })` once for a project. The durable history directory is external and private; it may be shared across that project's run directories. Existing callers without this option preserve their behavior. This integration covers the supervised `runTask` pipeline; native executor archives remain a separate evidence format and are not relabelled as supervised receipts.

A stable reservation is persisted before execution. After the actual workflow has settled its authority and saved its existing artifacts, the history bridge pins the exact receipt, check arrays, source phases and independent review. It delegates validation and deduplication to `OwnerRunRecorder`. Completed, failed and owner-blocked workflows retain their actual outcome. No summary, embedding request, schedule activation or external delivery is triggered by recording.

The optional `verifyIndependentReview` callback is trusted host code, never a task/model field. It receives the task, exact candidate source, saved review digest and private path. It must return true only after establishing that the reviewer did not implement those exact bytes. A model PASS or a hash alone does not establish independence. Without this attestation, review-bearing history remains explicitly incomplete, even if the underlying task completed. Fixture dependencies are labelled fixture; authenticated is a structural owner/session route label, not a claim that JSON proves provider identity.

History writes have separate source-bound artifact-only policy receipts with zero model requests. A failed history import never retries model execution, rewrites the original task outcome or masks its primary exception. Successful task results include a separate `history` disposition. Failure paths leave private immutable history status and policy artifacts under the run directory. An unavailable filesystem can prevent even the status file; inspect the durable policy ledger and original workflow artifacts.

For recovery, call `recoverAutomaticRunHistory(historyOptions, { workspace, runDirectory, taskId, execution, maxRuntimeMs })`. Recovery requires the original reservation marker and stored reservation. It retains the original terminal timestamp and exact manifest bytes; it imports evidence rather than replaying execution. Each persistence attempt has its own immutable status and policy receipt. Conflicting/revoked imports remain rejected. New execution using a prior run directory is refused; only explicit recovery may reuse its reservation.

This is a configured host API, not a background daemon or automatic migration of historical/native runs. Native-provider B024 remains a separate dependency. Missing check artifacts are not fabricated, and malformed or unbound existing evidence leaves recording incomplete.

Cleanup independently attempts recorder close, policy finalization/export and authority close. Cleanup faults leave a separate best-effort artifact-only note and an incomplete history disposition, preserving the original task result or exception. If the original terminal timestamp was never saved, explicit recovery stays incomplete; it does not use recovery time as an execution fact. Such missing evidence requires a separate owner-attested historical import policy.
